# Lab 06 · UAT and training release

**Business owner:** BA. **Release owner:** Technical Manager. Developer/Tester supply evidence.

1. Identify one candidate SHA and its requirement version, automated checks, independent QA, and defect retests.
2. The BA performs the agreed business scenarios and records acceptance or rejection with the candidate and evidence.
3. Complete [the release checklist](../../docs/release-checklist.md). Record open defects, missing checks, scope limits, deployment and rollback effects.
4. Use the release-readiness skill to draft an assessment and notes. Check every claim against actual evidence.
5. The Technical Manager records the real technical/merge/training-release decision. Keep incomplete requirements open even if a partial implementation PR merges.
6. If approved, use GitHub's release interface to create a training release tied to the accepted commit. Document demonstrated behavior and deferred work. This is a participant exercise; the starter has no automatic release or deployment workflow.

**Deliverables:** candidate-specific UAT, QA/technical decisions, release checklist and notes, actual release only if approved.

**Exit:** the team can trace one approved business change through its implementation, tests, acceptance, and release record.
