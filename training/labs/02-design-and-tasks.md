# Lab 02 · Design and bounded issues

**Lead:** Developer. **Approach owner:** Technical Manager. **Partner:** Tester.

1. Read the approved requirement version and [starter architecture](../../docs/architecture.md).
2. Use the change-analysis skill to propose the smallest first increment. Define state, input/output/errors, validation, identity/access, consistency, and the relevant test layers.
3. Record technical options and limitations in `docs/decisions/ADR-001-rqc-design.md`. Distinguish an in-memory training increment from a SQL-backed implementation.
4. Create bounded implementation issues with linked criteria, dependencies, tests, completion criteria, and rollback implications. Separate UI, persistence, and hardware work if they cannot be verified together.
5. The Tester reviews the test approach. The Technical Manager records the actual approach decision.

**Deliverables:** design PR/ADR, linked implementation issues, dependency and test plan.

**Exit:** a task satisfies the Ready conditions in CONTRIBUTING.md. The Developer can describe exactly what will be demonstrated and what remains deferred.
