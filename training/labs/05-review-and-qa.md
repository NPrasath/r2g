# Lab 05 · Review, defects, and verification

**Leads:** Technical Manager and Tester. **Fix owner:** Developer.

1. The Technical Manager inspects the PR against the approved criteria and uses Technical Reviewer as an additional evidence-based pass.
2. The Tester executes the planned cases on a named candidate and records expected/actual result, commit/environment, status, and evidence.
3. Report real failures with the defect form. Keep review risks and hypothetical exercises labeled separately from reproduced defects.
4. The Developer supplies focused fixes and regression tests where useful. Record commands actually run on the fixing commit.
5. The Tester repeats failing cases and affected regression checks; retain earlier failures and add the retest record.
6. Update the PR with the final technical review, QA assessment, open defects, and missing checks.

If no real defect appears, practice writing a clearly labeled hypothetical defect report; do not claim a reproduction. See [the facilitator guide](../facilitator-guide.md).

**Deliverables:** technical findings, test executions, real defect/fix/retest links if applicable, residual-risk record.

**Exit:** the tested candidate and remaining limitations are clear enough for BA UAT. QA and technical decisions remain human decisions.
